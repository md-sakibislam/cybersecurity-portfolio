\# Documenting Incidents with an Incident Handler's Journal



\## Project Description

A practical exercise in incident documentation using a structured journal template —

capturing the 5 W's (Who, What, When, Where, Why) for a cybersecurity incident,

along with tools used and follow-up questions for further investigation.



\## Entry 01 — Ransomware Attack (Healthcare Company)



| Field | Detail |

|---|---|

| \*\*Date\*\* | July 22, 2026 |

| \*\*Who\*\* | An organized group of threat actors |

| \*\*What\*\* | Ransomware attack |

| \*\*Where\*\* | A healthcare company |

| \*\*When\*\* | Tuesday, 9:00 AM |

| \*\*Why\*\* | Employees received phishing emails containing a malicious attachment; the incident was triggered when an employee opened the attachment |



\*\*Follow-up questions raised:\*\*

\- How can this type of incident be prevented in the future?

\- Should the ransom be paid to recover the encryption key?



\## What This Demonstrates

Structured incident documentation using the 5 W's framework to capture the

essential facts of a security incident — attribution, method, timing, location, and

root cause — in a format suited for handoff, review, or escalation.
